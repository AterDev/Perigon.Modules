# 私有资源及个人添加资源

有两个场景需求：

1. 用户想添加自己的资源，仅自己可见。
2. 用户想补充资源，以作为公开资源的一部分。

## 功能设计

- 用户添加资源入口，在添加时选择资源类型，选择是私有还是申请公开。
- 用户可以查看自己的资源列表(包括私有和申请的资源状态)
- 如果是申请公开，则在后台可以查看到，管理员审核通过后，可补充环境、分类、分组和标签，并将申请转换为常规资源(即通过后台流程添加的资源)。
- 私有资源不关联环境、分类、分组或标签。

## 实体逻辑说明

- 新增 `UserResource` 实体(不是 PersonalResources)， 拥有可见状态与审核状态字段。
- 通过 `UserId`与所属用户关联，不直接关联实体类型 。
- 新增 `UserResValue`，用来存储用户资源具体的属性值。
- 提供个人资源的创建、查询、编辑、删除及“我的资源”接口。
- 提供管理员待审核列表、通过和拒绝接口。
- 公开申请通过后创建常规 `Resource`
- 复用常规资源属性校验和规范化逻辑。

## 用户收藏资源

指用户可以收藏公开的资源，实现也相对简单，添加一个`UserFavoriteResource` 实体，用来存储用户收藏的资源信息。

它包含`UserId`与`ResourceId`，用于标识用户与其收藏的资源，以便关联查询出来 resource相关属性和属性值。

添加对应的Manager和Controller，提供收藏，取消收藏，查询收藏等接口。

实现约定：收藏接口使用当前登录用户的 `UserId`，只允许收藏当前用户按常规资源权限可见的 `Resource`；私有用户资源和待审核申请不会直接进入收藏表。收藏记录通过 `ResourceId` 关联资源详情及 `ResValue`，提供 `mine` 分页查询、指定资源详情、收藏和取消收藏接口，重复收藏返回冲突，取消后可再次收藏。
